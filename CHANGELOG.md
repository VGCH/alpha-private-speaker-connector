# Changelog
## 2.2.3
- Восстановлена ссылка на веб-панель колонки в карточке устройства Home Assistant (`http://<IP-колонки>:8000`).
- Добавлен разбор IPv4/IPv6 адреса из gRPC `context.peer()`; URL обновляется при повторном подключении колонки.
- `configuration_url` передаётся напрямую в `DeviceInfo`, совместимо с Home Assistant Core 2026.11+.

- Исправлена совместимость с Home Assistant, где уже установлен protobuf 7.x: снято ограничение `<7.0`.
- Сгенерированный protobuf-код требует runtime не ниже 5.29.0 и совместим с более новыми runtime.

- Упрощён config flow: убрана необязательная фиксация unique_id.
- Добавлен совместимый импорт ConfigFlowResult.
- Проверка единственного экземпляра выполняется через публичный ConfigEntries API.

# Changelog

- Исправлена сериализация `DeviceState.attributes` для protobuf `map<string, string>`.
- Подписка на `state_changed` устанавливается до отправки initial snapshot.
- Начальный снимок и последующие события отправляются через один gRPC-поток.
- `last_changed` и `last_updated` берутся из исходного состояния Home Assistant.
- Убраны пустые keep-alive сообщения `DeviceState`, которые могли попадать в callback клиента как сущности без `entity_id`.
- Исправлен вызов асинхронного `context.abort()`.
- Добавлены проверка регистрации колонки и фактическое ограничение `max_speakers`.
- Добавлена очистка TTS futures, очередей и подписок при остановке/отключении.
- Исправлена генерация session ID и ID сообщений.
- Добавлена очистка подписок платформ при выгрузке интеграции.
- Исправлены начальные/динамические сущности для колонок и media player; удалён разбор speaker ID по первому подчёркиванию.
- Конфигурация больше не требует неиспользуемых HA URL и long-lived token.
- Удалён runtime-пакет `grpcio-tools`; зафиксированы минимальные совместимые версии gRPC/protobuf.

### Совместимость

Существующие имена RPC и protobuf-поля сохранены. Для этой версии не требуется перегенерация protobuf на клиенте.
